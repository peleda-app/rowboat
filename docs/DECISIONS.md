# Decisions

What was decided and why. Decisions of the layers before the merge stay in `baton/docs/DECISIONS.md` and in Skein's history; this file starts with the merge.

## 2026-11-25: the merge (stage 4 of the workspace reorganisation)

Decided by the maintainer:

- **One repository, three layers.** `skein` (this repository's git history, GitHub `peleda-app/skein`), `baton` (no commits) and `smereka` (documents only) become `rowboat`, Peleda's node. `baton/` is coordination, `skein/` the mail engine, `crates/` and `apps/` the node (empty for now).
- **Public, PolyForm Noncommercial 1.0.0.** Commercial use needs a license from the maintainer; contributions need the signed CLA (`CLA.md`, synced from dojo).
- **Names.** Crates keep `skein-*` and `baton-*`; the node's own crates will be `rowboat-*`.
- **No web interface, no HTTP management API.** The web portal, the TypeScript client, `openapi.json`, the HTTP management API of `skein-server`, and the HTTP server and HTTP follower of `skein-view` go away. A minimal inbound endpoint stays for Gmail Pub/Sub and Microsoft Graph change notifications (`skein-push`, with their authenticity checks) and a health check. The node is managed through Baton commands from the app, later.
- **The rule against describing the mesh is gone.** Skein's local note that Skein is the open part and must not describe the mesh, device nodes, pairing, the relay or the hosted node no longer applies and was removed; the rest of that note stays, in `AGENTS.local.md` at the root and in `skein/`.
- **Uncommitted work moves along.** Skein's 153 uncommitted changes (the switch to Baton contracts) were moved into `skein/` uncommitted, byte for byte apart from the edits listed below.

Taken without the maintainer, with reasons:

- **Plain moves, two workspaces for now.** Every Skein file at the root moved into `skein/` with `mv` (git sees the renames once staged); Baton was copied into `baton/` without `.git` and build output; `../baton` and `../smereka` stay on disk untouched. `skein/Cargo.toml`'s `../baton/crates/...` paths now resolve inside the repository, so neither layer's build changed. One workspace and one `Cargo.lock` are a separate next step (reconciling `hmac` and `sha2` versions and the rustls crypto provider), so that the move itself changes nothing that compiles.
- **Root `mise run check`** runs `mise run check` in `baton/`, then in `skein/` (both unchanged), then `dojo check .` through `../dojo`, as `rinse` does.
- **`dojo.toml` excuses `LIC-PUBLISH` for `skein` and `baton`.** Every member inherits `publish = false` from its layer's `[workspace.package]` (or sets it), but with no root `Cargo.toml` dojo resolves `publish.workspace = true` only against the repository root and reports all 71 members. The two entries go away when the layers become one workspace.
- **License files.** No full PolyForm text is on this machine and none may be downloaded, so `LICENSE.md` names the license, gives its official URL (the license allows giving recipients the URL instead of a copy) and the Required Notice "Copyright 2026 the rowboat authors"; the licensor's name and the full text are a question for the maintainer. Cargo `license` is `PolyForm-Noncommercial-1.0.0` in both layers' `[workspace.package]` and both fuzz manifests; `publish = false` is set in both workspaces and every member inherits it (`publish.workspace = true` was added where it was missing); `documentation` links to docs.rs were dropped and the `repository` and `homepage` fields point at `peleda-app/rowboat`. The four `package.json` files carry the same license; `openapi.json` and its source say so too until they are removed.
- **Publishing removed.** `release.yml` and `skein/release-plz.toml` existed only to publish crates to crates.io and the client to npm and were deleted; the npm job left `publish.yml`, and `packages/client/scripts/prepare-publish.ts` and the client's `publishConfig` went with it. `publish.yml` keeps the signed, attested container images and binary archives, built from a tag `vX.Y.Z` pushed by the maintainer (it runs only in `peleda-app/rowboat` and only with `RELEASES_ENABLED`). `skein/docs/RELEASING.md` describes it.
- **Images are named rowboat.** `ghcr.io/peleda-app/rowboat` (with `-headless` tags) and `ghcr.io/peleda-app/rowboat-view`; archives are `rowboat-vX.Y.Z-<target>`. The binaries inside keep their crate names (`skein`, `skein-view`) until the node layer has its own binary.
- **Docker builds use the repository root as context.** `skein/Dockerfile` and `skein/apps/view/Dockerfile` copy `baton/` and `skein/` and build in `skein/`; the root `.dockerignore` replaces Skein's.
- **Workflows at the root run per layer.** CI's `check` job checks out the repository at `rowboat` and dojo beside it and runs the root `mise run check`; integration, load and live run in `skein/`; the image job builds all three images from the root; `cargo deny` and the fuzz workflow run once per layer (Baton gained a fuzz job it did not have). The `pre-push` hook in `.git/hooks` stays: it blocks pushes until the GitHub repository is renamed.
- **Docs site and links.** The site's base moved from `/skein` to `/rowboat` (GitHub Pages of the renamed repository) with every internal link; GitHub links point at `peleda-app/rowboat/blob/main/skein/...`. The site still documents the HTTP API until the removal reaches it.
- **`deny.toml`** at the root and in both layers is dojo's template. The layers' old copies lacked `[licenses.private] ignore = true`, so `cargo deny` would have refused the repository's own `PolyForm-Noncommercial-1.0.0` crates; with `publish = false` they count as private and are skipped. CI runs `cargo deny` per layer until the workspaces are unified. `cargo-deny` is not installed on the machine that made this change, so this was not run locally.
- **The app** points `baton-seal` at `../rowboat/baton/crates/seal`, checks out `peleda-app/rowboat` in CI and mounts `../rowboat` in its Linux container; `bento` and `peleda-insight` have no path dependencies on Skein or Baton and were not changed.
- **dojo's registry** lists `rowboat` as `active` and `skein`, `baton` and `smereka` as `retired`.

## 2026-11-25: one Cargo workspace

Taken without the maintainer, with reasons:

- **One workspace, one `Cargo.lock`, one toolchain, one `deny.toml`.** The root `Cargo.toml` lists `baton/apps/*`, `baton/crates/*`, `baton/tests/load`, `skein/apps/*`, `skein/crates/*`, `skein/tests/integration` and `skein/tests/load`; `skein/apps/docs` and `skein/apps/portal` (bun projects) and both fuzz crates are excluded. The layers' `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `deny.toml` and `mise.toml` are gone; their content lives at the root. The lock was seeded from both layers' locks so no dependency moved to a version neither layer had tested; where the two locks disagreed the newer one was kept (`hyper` 1.13.0, `zerocopy` 0.8.65). Lints were already identical; Baton's `opt-level = 3` dev overrides for `argon2` and `blake2` are kept.
- **One `hmac` and one `sha2`: 0.13 and 0.11.** Baton's only direct use of `hmac` 0.12 and `sha2` 0.10 was the invite proof in `baton-identity` (HMAC-SHA256), which needs neither version: `ed25519-dalek` uses `sha2` 0.10 internally and still does, transitively. `baton-identity` moved to the workspace entries (one import of `KeyInit` added); HMAC-SHA256 output is the same in both versions and its 11 tests pass. `baton-seal` and `baton-keys` dropped the `sha2-v0-11` alias for plain `sha2`. No second key was needed.
- **aws-lc-rs is the only rustls crypto provider.** Baton needs it for the hybrid post-quantum `X25519MLKEM768` group that `baton-link-iroh` requires. Skein's `tokio-rustls` entry switched from `ring` to `aws_lc_rs` (keeping `tls12` and `logging`), `rcgen` uses Baton's `aws_lc_rs` and `pem` features without defaults (its default turns on `ring`), and the three places that picked `ring` explicitly (`skein-core`'s test TLS acceptor, `skein-mail-imap`, `skein-send-smtp`) pick `aws_lc_rs`; `jsonwebtoken`, `reqwest` 0.13 (`rustls`) and `iroh` already used aws-lc-rs. `cargo tree -e features -i ring --target all --all-features` prints nothing, so `ring` is never compiled; it stays in `Cargo.lock` only as an optional dependency of `rustls-webpki` and `quinn-proto`. Every TLS configuration in the repository names its provider (`builder_with_provider`), and with a single provider compiled rustls' process default cannot be ambiguous, so no process installs a default. `baton-link-iroh`'s tests that check the negotiated group and refuse classical-only peers pass in the workspace.
- **Feature unions.** `axum` takes Skein's defaults (Baton had `http1` and `tokio` only; the defaults add `json`, `query`, `form`, `matched-path`, `original-uri`, `tower-log` and `tracing`); `hyper` adds `http2` and `hyper-util` adds `server-auto` for Baton; `reqwest` adds `socks` and `stream` for Baton's `baton-mailbox-drop`; `tokio-rustls` adds `logging`; `tracing-subscriber` takes Skein's defaults plus `env-filter` and `json` (Baton had no defaults). The last change would turn on ANSI colours and the `log` bridge in Baton's binaries, so `batond` and `drop` now call `.with_ansi(false)` and print as before; the `log` bridge means records of dependencies that log through `log` reach their INFO output. Baton's log test (no box ids, keys or addresses at TRACE) passes with the union.
- **One `mise run check`.** It runs everything both layers' checks ran (Baton's unsafe scan, fmt, clippy and tests over the workspace, Skein's `otel` and `portal` feature builds and the bun checks), plus `cargo fmt --check` and `cargo check --bins` on stable for both fuzz workspaces as dojo's template does, then `dojo check`. The fuzz crates' targets were reformatted once with `cargo fmt` (layout only) and set `[lints.rust] unsafe_code = "forbid"`, which dojo requires of crates outside the workspace.
- **Fuzz workspaces stay per layer.** Each keeps its pinned nightly, corpora, lockfile and `run.sh`; merging them would move Skein's uncommitted targets and corpora and every fuzz path in CI and docs for no gain. `dojo.toml` excuses `TEST-FUZZ` at `fuzz` for that reason, and the two `LIC-PUBLISH` exceptions are gone since every member now inherits `publish = false` from the root.
- **Tasks are named per layer where they differ.** `load-baton`, `load-skein` (`load` runs both at their default sizes), `fuzz-baton`, `fuzz-skein`, `fuzz-all`, `fuzz-build`; `it`, `it-down`, `live`, `client` and `deny` keep their names. All run from the root.
- **CI and images follow.** CI's `check` job caches the root, both fuzz workspaces and dojo; integration, load and live run from the root through `mise`; `cargo deny` runs once on the root manifest. The Dockerfiles copy the root `Cargo.toml`, `Cargo.lock` and `rust-toolchain.toml` with both layers and build in `/src`; `publish.yml` reads the version from the root `Cargo.toml` and builds the archives from the root.
- **`skein`'s `anyhow` dev-dependency** now uses the workspace entry (dojo `MOD-WORKSPACE-DEPS`).

## 2026-11-25: the portal and the HTTP management API removed

Carried out as the maintainer decided (see the merge section): the portal, its feature, `rust-embed` and Docker stage, the bun steps, `@peleda-app/skein-client`, `openapi.json` and `utoipa`, the management routes of `skein-server` with their auth machinery, the docs site's API reference, and `skein-view`'s binary, HTTP API, HTTP follower and image are deleted.

Taken without the maintainer, with reasons:

- **`skein-server` keeps its name and becomes the inbound listener.** It serves `GET /v1/health` and the Gmail and Graph push routes, nothing else (every other path is 404). The `/v1` prefix stays on these paths because Graph subscriptions and Pub/Sub push subscriptions are registered with them. `router(signal, push, &config)` replaces `router` and `router_with_push`.
- **A push rate limit was added.** The task asked to keep the push receivers' rate limits, but they had none: the per-key limiter belonged to the management API. One token bucket per receiver (`push_rate_per_second`, default 100, 429 with `Retry-After: 1`, which both providers retry) bounds the storage reads a flood can cause; health is not limited. Review on the same day: a single bucket in front of authentication let forged requests starve genuine pushes, so Gmail spends its token only after the path secret matches and Graph has its own bucket; a Graph flood can still delay Graph pushes (they fall back to polling), since Graph has no secret before the body is read. Body limits (64 KiB), the 30 s body idle timeout, the header timeout and the connection cap stay.
- **The metrics listener stays, on loopback only.** It is observability, not management, and serves only `/metrics`; the inbound listener serves only push and health. Review on the same day: the maintainer allowed only push and health inbound, so `metrics.listen` must be a loopback address (anything else fails `check-config`), metrics leave the host only through OTLP, and whether to drop the listener altogether is question 21.
- **Management moved to the binary's subcommands** (`skein tenant`, `account`, `journal`, `webhook`, `push-token`), which open the node's storage and master key file and write through the same stores. Secrets come from stdin. The checks the routes ran moved into libraries so Baton commands can reuse them: `skein_engine::{check_command, submit_command, cancel_command}` and `skein_accounts::admin` (record, password, send key and token checks, tenant register, unregister and purge, account deletion). A command queued from the command line is hinted only in its own process, so the owner picks it up on its next round (at most `engine.interval_secs`).
- **Dropped with the API, not ported:** API keys, scopes, IP allowlists, trusted proxies, the per-key rate limits and stream caps, CORS, the account host policy (`account_hosts`: only the operator writes records now), OAuth sign-in through the server and its callback and pending sign-ins (the app will sign in and hand tokens over; `skein account grant` does it today), webhook test pings, and `traceparent` from request headers. `[server.webhooks]` moved to `[webhooks]`; OAuth clients no longer need `redirect_url`. The removed config keys are refused, so an old config fails loudly.
- **Outgoing webhooks stay.** `skein-webhooks` never depended on the API; its endpoints are managed with `skein webhook`. Whether Peleda needs them is question 17.
- **`skein-sse` stays**: `skein-mail-jmap` uses it for JMAP push.
- **`skein-view` became a library in `skein/crates/view`**, following a tenant's journals straight from the storage contracts: heads checked with a `HeadAttestor`, segments read through `Chain` and checked with `verify_segment` like the tiered storage does with untrusted tiers, the last fully applied segment stored (schema version 3) so a rolled-back head or swapped history is refused, compaction answered with the latest snapshot. It wakes on the engine's `heads/{account}` signal hints when given a signal. Its query API is the `Store` the HTTP API used, with every list capped at 1000 rows; the app will embed it.
- **Tests ported, not dropped:** command checks and cancelling (to `skein-engine`), record, SES and secret checks, sealing and purge (to `skein-accounts`), the listener, header, body and push tests (kept in `skein-server`), every `skein-view` end-to-end scenario (to the library, plus attack tests), the binary end-to-end scenario (to the subcommands, in `binary.rs` and the new `apps/skein/tests/cli.rs`). Deleted because they tested the removed API itself: key auth, scopes, admin routes, cross-tenant key walks over `openapi.json`, IP allowlists and trusted proxies, rate limits and stream caps per key, CORS, the account host policy, the OAuth start and callback flow, event paging and 410, blob ETags, the SSE stream, webhook routes and test pings, the OpenAPI drift and operation id tests, the portal's file serving, view's REST routes, token auth and CORS, and the HTTP request-parsing property tests (the path and label properties are ported to `skein-engine`). The load tests never used HTTP.
- **Images.** One image, `rowboat`; the `-headless` variant and `rowboat-view` are gone (question 15 resolved). The docs site keeps its own `bun.lock`, pruned by hand of `starlight-openapi` and the 74 packages only it pulled in, since no download was allowed.

## 2026-11-25: review of the restructuring

Taken without the maintainer, with reasons:

- **Push rate limits after authentication.** Gmail spends its token only after the path secret matches, and Graph has its own bucket, so forged requests cannot starve genuine Gmail pushes (test: a flood of wrong-secret and Graph requests, then a genuine Gmail push still answers 204). A Graph flood can still delay Graph pushes; question 20.
- **`skein-view` rebuilds only forward.** A missing segment was taken as compaction and the latest snapshot replaced the account's state, checkpoint and tip whatever its `seq`, so whoever could write storage could roll a follower back or past the head. A snapshot at or before the checkpoint is now `Rollback` and one past the attested head is `Mismatch`, with nothing changed (two attack tests). Binding snapshots to the chain is question 19.
- **`metrics.listen` must be loopback.** Only push and health may listen beyond the host; question 21 asks whether to drop the listener.
- **`skein journal get-blob` writes a new owner-only file** (mode 0600, `create_new`, so an existing path or symlink is refused), like `skein export`.
- **Secrets are never typed into a terminal.** The commands that read secrets from stdin refuse a terminal and ask for a pipe or file, rather than echoing the secret; no new dependency was added for hidden input.
- **`baton/mise.toml` deleted**, as the restructuring entry above already stated; `mise run check` from `baton/` now runs the root check.

Taken without the maintainer, with reasons:

The contracts `baton-signal`, `baton-wake` and `skein-keyring` gained unit tests of their pure parts (dojo `TEST-PRESENT`).
- **Known deviations from MOD-1 and MOD-2, labels kept.** `skein-storage` is labelled `contract` but is not only one: beside its traits, types and suite it holds implementations of its own traits on top of `Objects` (`ObjectLog`, `ObjectControl`, `ObjectCommands`, `ObjectBlobs`, `CountingObjects`) and `ControlState`, an adapter onto `baton-state`'s `StateStore`. `contract` is closer to the truth than `library`, which would only dodge the suite check; the honest fix is a split (question 22). Unsafe code stays forbidden by the workspace lints and by the fuzz crates' own lints.
- **Both `fuzz/run.sh` are dojo's shared copy**, which adds per-target seed directories and keeps each fuzz workspace's build in its own `target/`. cargo-fuzz 0.13 finds a project by walking up past the fuzz crate to the next `Cargo.toml`, which for `baton/fuzz` and `skein/fuzz` is the root manifest, so `cargo fuzz` run from either directory looks for `fuzz/` at the root and fails; this predates the change. Baton's `fuzz/corpus` is gitignored, so the `keys_box` seed lives in the tracked `baton/fuzz/seed-corpus/keys_box`, listed in `baton/fuzz/seeds`.

## 2026-11-26: license keys

Decided by the maintainer:

- **rowboat stays public under PolyForm Noncommercial 1.0.0**, free for personal use and noncommercial organizations with no key.
- **Three additional licenses granted by Peleda**, automatically where possible: a free Small Team License (any purpose, up to 5 users counted with affiliates, no service to third parties, issued after a confirmed address and accepted terms); a free Organization License (human-rights organizations, press freedom and investigative journalism, legal aid, digital rights, refugee aid; by application, decided by the maintainer, one year, renewable, revocable on stated grounds; not governments); a paid Commercial License (companies above 5 users and hosting providers, through hallway's merchants of record).
- **A key is a signed certificate, not a lock**: verified offline against embedded public keys, shown in the app, never phoning home, no telemetry, never blocking anything; honest notices only. Revocation by one-year expiry and a list shipped with updates, never fetched behind the user's back. Licensees screened against sanctions lists with the sanctions repository; licensee data minimal.
- **The plan includes the implementation of the keys** (format, hierarchy, ceremony, rotation, compromise, verifier): [LICENSING.md](LICENSING.md).

Taken without the maintainer, with reasons (from three independent designs, judged field by field; the security-first design is the base):

- **Format.** Postcard `{ version, body, signature }` with a versioned body and `context || 0x00 || body` framing, as hallway's signed statements and Baton's `sign(context, message)` do, Ed25519 with `verify_strict`, sizes checked before signatures, and a canonical rule (decode, re-encode, compare) so no second spelling of a certificate exists. JSON, JWT and X.509 were rejected for their parser surface and non-canonical forms. No extensions field: a new field is a new version.
- **Roles per issuing key.** Separate Small Team, Commercial, Organization and revocation keys under two offline roots, so a leak of the online Small Team key can mint only Small Team certificates and no online key can sign revocations. One shared automatic key (one of the designs) was simpler but widened the blast radius for little saving.
- **Verify ignores the clock; status uses a monotonic floor.** A wrong clock changes what is shown, never what is accepted; rollback cannot revive a license past times the node has seen.
- **Sticky revocations instead of an unbounded union.** The node keeps the newest list plus every revocation it has seen for its installed certificates, issuers and roots, so a leaked revocation key cannot revive anything while the issuer can drop long-expired serials.
- **Scope as a bitset with unknown bits invalid**, adding `SERVICE_TO_BENEFICIARIES` for the Organization License: the right the base license and Small Team lack, and the main reason a registered charity would want the license.
- **Holder keys optional.** A key requested from the app carries the owners' Baton member keys (proof of possession), which shows a copied certificate as not bound; a key requested on the web carries none. Binding never blocks.
- **Text outside the armor is ignored and never shown**, rather than human headers that must match the body: readable files with a smaller parser.
- **Two crates in rowboat:** `rowboat-license` (pure, no Baton dependency, so hallway can depend on it by path under LIC-5 without pulling in Baton) and `rowboat-licensing` (service crate over `StateStore` and `GroupState`, no network crates). Format and vectors in one place, so issuer and verifier cannot drift.
- **Users are member keys with a live, non-blind node certificate**, deduplicated across the groups a node serves; shown as "about N"; the contract's definition governs.
- **Notices only for owners and admins, only in Settings, dismissible for 90 days, no operating-system notifications**; none ever for a group without a certificate on a phone or desktop. Renewal reminders come by mail from the issuer.
- **Phases are named L0 to L9** so they do not collide with the repositories' own numbering; L1 starts now since it does not need the node layer.
- **Question 12 is resolved** by this decision; the README's license section names the three licenses and the placeholder URL `https://peleda.app/license`. New questions 24 to 37.

## 2026-11-26: license plan revised after review

Taken without the maintainer, with reasons (review findings on [LICENSING.md](LICENSING.md)):

- **Revocation cannot be frozen by one stolen revocation key.** Two distinct revocation keys A and B on separate tokens, both pinned by every release; list numbers may grow by at most 2^20 per list; a list naming the stored list's signer in `issuers` replaces it whatever its number; a release resets a list whose signer it no longer pins or that its embedded list revokes; a list's `issued_at` must lie in its key's window; sticky entries remember their signer and go when it is revoked. The Organization issuer moves to its own token (O), so one theft plus one PIN breaks one role.
- **Dates bounded by the delegation.** `not_before <= issued_at + 31 days` and `not_after <= issuer.not_after + max_license_days`, so a leaked or retired issuing key cannot mint certificates for later years; old seeds are destroyed 30 days after the switch. Kind caps (365 days for Small Team and Organization, 400 for Commercial) are separate from the issuer cap, so the Organization issuer (400) can sign hand-made Commercial deals with grace. Windows: 15 months for issuing keys, 25 for revocation keys.
- **Lists fit a Baton command.** `MAX_REVOCATIONS` is 48 KiB (2 500 serials, 64 keys, 8 roots, all sorted and unique) so `license-revocations` stays under Baton's 64 KiB `MAX_ENCODED`; armored lists have their own 72 KiB limit. Deltas or peer fetch are question 38.
- **Server licenses belong to the operator.** On the server profile only the configured operator key (or the owners of the operator group) manage the license and see counts and notices; hosted groups see that the operator manages it, nothing else.
- **Holder keys are licensing-only keys, binding is opt-in.** The app creates them; the link to a member exists only on the node (`holder_proof` at install). Certificates no longer carry Baton member keys.
- **`ServiceWithoutLicense` only with an installed certificate.** With no key installed no notice ever appears.
- **The clock floor is recomputed from signed values**, with the observed clock capped at signed values plus 35 days and resettable by owners (`license-reset-clock-floor`), and cleared when no certificate is installed.
- **Requests reach the page in the URL fragment or as a file**, never in a query string; single use; a leaked request locks nobody out because the app makes new holder keys.
- **Versions down the chain**: every object's wire version is at least its signer's `min_version`.
- **Display names**: Unicode categories Cc, Cf, Co, Cn, Zl, Zp refused; Small Team certificates carry no name (nobody checks it); Commercial names are checked against the payment record.
- **One renewal window**: requested from 60 days before the end, `not_before = max(issued_at, old not_after − 30 days)`.
- **L5 split** into L5a (device and app, part of the go-live gate) and L5b (server, with phase 3).
- **"Reissue" means a new serial**; downloading the same certificate again is "download".

## 2026-11-26: node phases 0 and 1 built

Taken without the maintainer while building [NODE.md](NODE.md), with reasons:

- **`rowboat-node` is a `library` in dojo's terms although it is a composition root** (a node builder, MOD-4): dojo has no kind for a composition library, as for the app's `peleda-core`. It depends on implementations (`skein-storage-fs`, `skein-storage-sealed`, the IMAP and SMTP providers, Baton's CAS leases, the hooks) and picks them per profile.
- **The test profile keeps sealed file storage** instead of memory objects, so restart and lock tests run over the same directory; it differs from the desktop only in its providers and timing.
- **`skein-view`'s parser hook returns the existing `Parsed`** (now with `tags`) instead of a new `ParsedMessage` type: the fields are the same and the default `mail-parser` path keeps working unchanged. The hook gets a `ParseContext` (account, mailbox, the mailbox's role from the same page or the database) so the spam hook can see junk placement. The parser's version is stored per message; lazy re-parsing on a version change is not built yet.

Defaults taken for the maintainer's questions, with reasons:

Taken without the maintainer while building, with reasons:

- **Typed causes as new variants, not a field.** `MailError` gains `Insecure`, `Quota`, `Refused`, `Tls` and `Timeout`; `SendError` gains `Tls`, `Insecure` and `Timeout`; both gain `cause()` returning a closed, serializable kind (`MailCause`, `SendCause`). New variants keep every existing constructor and `match` meaningful and let the compiler find each place that must decide; a cause field on `Network(String)` would have touched every one of some 400 construction sites for no gain. `MailError::connection_lost()` (Network or Timeout) replaces every `Network(_)` pattern that meant "the outcome is unknown", so the engine still reports an interrupted write as uncertain. `SyncOutcome` gains `tls`, `insecure`, `timeout`, `quota` and `refused` (older readers see `other`).
- **Where each cause comes from.** IMAP: a timeout is `Timeout`; a failed handshake or certificate, or TLS on a plain port, is `Tls`; a missing STARTTLS or plain text to a remote host is `Insecure` (was `Config`); a tagged `NO` is `Refused` (was `Protocol`), or `Quota` with `[OVERQUOTA]`; a `BYE` greeting is `Refused` (was `Network`). SMTP: handshake failures are `Tls` and a missing or refused STARTTLS is `Insecure` (both were `Unavailable`); a deadline missed before the message was complete is `Timeout`; plain text to a remote host is `Insecure` (was `Invalid`). The HTTP providers (JMAP, Gmail, Graph) report timeouts as `Timeout` and keep TLS failures under `Network`, since `reqwest` does not expose a TLS kind without matching texts.
- **The node maps causes, never texts.** `errors::mail` and `errors::send` match on `cause()`; the old substring tests (`"TLS"`, `"certificate"`, `"plain"`) are gone, and a test feeds texts full of those words to show they no longer steer the mapping.
- **A silent server is unreachable.** `Timeout` maps to `ServerUnreachable`, as the old "sent no greeting" text did; `NodeError` keeps its kinds, so the app needs no new error kind.
- **Probes are functions in the provider crates**, as NODE.md change 9 says, with a `timeout` argument added: the whole probe (connect, TLS, greeting, capabilities) runs under one deadline. The IMAP probe reads at most 64 KiB in at most 64 lines of 8 KiB, keeps at most 64 capabilities and requires `IMAP4rev1` or `IMAP4rev2`; the SMTP probe reuses the session code with no login, so it reads replies through the same capped reader as sending. Neither runs in plain text, whatever the host; local bridges are entered by hand and signed in by `add_account`, which keeps its loopback rule.
- **The IMAP STARTTLS wait is now bounded by lines too** (64 untagged lines before the answer to `STARTTLS`); before, only time bounded it.
- **`Prober` returns what it learnt.** `probe_imap` and `probe_smtp` return `Result<Probed, DiscoverError>` instead of `bool`, so discovery can tell OAuth-only servers (the hint becomes `OAuthOnly`) and servers that take no password at all (dropped), and errors carry a kind. `DiscoverError` gains `Unreachable`, `Timeout`, `TlsFailed`, `Insecure`, `NotMail` and `TooLarge`.
- **`ServerProber` lives in `rowboat-node`**, the composition root, because it depends on two implementation crates (`skein-mail-imap`, `skein-send-smtp`), which an implementation crate may not.
- **Three crates for the new sources.** `rowboat-discover-autoconfig` and `rowboat-discover-srv` implement `DiscoverySource` over the contract's new `HttpsFetcher` and `SrvResolver` traits and do no I/O themselves; `rowboat-discover-net` implements both traits (`Https` over `reqwest`, `UdpResolver` over UDP). Fakes (`FakeFetcher`, `FakeResolver`, `FakeProber`) and suites (`testing::fetcher`, `testing::resolver`) live in the contract.
- **A small DNS client instead of a resolver dependency.** The workspace has no DNS library and nothing new could be downloaded; SRV over UDP needs one question and a bounded reader, which is also the decoder the task wants fuzzed. Name servers come from `/etc/resolv.conf` (at most 3); there is no EDNS, no TCP fallback (a truncated answer is no answer) and no DNSSEC. Answers are suggestions only: every host is probed with a verified certificate and needs confirmation when it lies outside the domain and the known providers. Random id, a fresh connected socket per question, only records owned by the asked name, backward-only compression pointers.
- **The table first, the network only for unknown domains.** When the table knows the provider, autoconfig and SRV are not asked at all, so setting up a well-known address sends nothing anywhere. The other sources are asked at once rather than one after another, to bound the wait by the slowest source.
- **Candidates from the network must keep two rules** (`Candidate::fit_from_network`): no IP literal, and STARTTLS only on 143 or 587, so a hostile autoconfig file or DNS answer cannot steer the client to an address or an odd port that starts in plain text. TLS on any port is accepted, since the certificate is verified.
- **`needs_confirmation` on `Candidate`** (serde default `false`) marks a candidate with a server outside the address's domain and the table's providers (`TableSource::known_host`); the app shows it as "suggested by" its source. Table candidates never need it.
- **The autoconfig fetcher sends a fixed user agent without a version** (`mail-client-autoconfig`), so the request says nothing about the build, and follows no redirect.
- **Re-parsing runs in the background only.** `Follower::reparse_stale` parses at most 50 stale messages after every round of `run` (the node's parser version joins rinse's, the spam filter's and the categorizer's versions, so a new rinse or bento triggers it). Re-parsing on read, which NODE.md also names, is not built: reads stay database-only and fast, and the background rounds catch up. Threads, memberships and the address book are kept; a message whose original is gone keeps its content and is marked with the new version so it is not tried again.
- **Not built in this step:** the integration and live suites (containers and the maintainer's accounts), the moved `push` crate (it lives in `../app`, where another session works), and calendar invitations (they wait for rinse).

## 2026-11-26: file storage shared between the server and its subcommands

Taken autonomously to fix two CI failures of commit `cc7ecd7`.

- **One owner, shared handles, a lock per write.** `skein-storage-fs` held an exclusive lock on `<root>/.lock` for the life of every handle, so with the HTTP management API gone (2026-11-25) a running `skein serve` could not be managed at all: every subcommand failed with "in use by another process". Now `FsObjects::open` (the server, the node, the load tests) still takes that lock as the directory's owner, so a second server is refused, and `FsObjects::open_shared` (the subcommands, export, import, copy) takes none. Every `put` and `delete`, from either kind of handle, holds an exclusive advisory lock (`flock`, `LockFileEx`) on one of 64 stripe files under `<root>/.locks` for its read-compare-write; writes stay atomic by rename and reads stay lock-free.
- **Why this is enough.** Every store above `Objects` (control records, journal heads and segments, blobs, the command queue, Baton's lease records) is made of compare-and-swap, so cross-process compare-and-swap keeps every guarantee they had: appends stay fenced, commands are created with `Expect::Absent`, two writers of a key see one success. Multi-process tests (children of the test binary) fail without the stripe locks and pass with them. Stripes are chosen by FNV-1a, not the standard hasher, so every process and build agrees.
- **No wake across processes.** The engine already re-reads tenants and accounts every heartbeat and an account's queue every round, so a command submitted from the command line runs within `engine.interval_secs`, which the integration test's deadlines allow. A hint file or a cross-process signal was left out until that latency matters; the node will take Baton commands anyway.
- **The node layer keeps its exclusive open.** `rowboat-node` calls `FsObjects::open`, whose meaning (owner, refused while another owner runs) did not change.
- **Linearity of group verification is counted, not timed.** `verifying_a_long_log_stays_linear` asserted under 20 s of wall time and failed on a slow runner (TEST-3 forbids wall-clock assertions). In test builds `baton-group` counts units of work per thread (one per applied entry, one per resource state copied); the test requires the work for 3,000 entries to be at most three times the work for 1,000 plus a constant. A state copy per entry, the quadratic shape it guards against, makes the ratio about nine and fails it. The timing check stays in the `group` load scenario, which already has an explicit budget.

## 2026-11-26: review fixes for notifications, folder settings and the file store

Taken autonomously after the review of the desktop batch.

- **Refused messages notify at most silently.** A message the content pipeline refused is stored unavailable, with no spam verdict and no category; notifications now count it as suspicious, so a sender cannot skip the spam check for alerts by crafting mail rinse refuses.
