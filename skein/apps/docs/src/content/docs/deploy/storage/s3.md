`skein-storage-s3` stores every object in an S3-compatible bucket. Compare-and-swap uses the store's conditional writes, so it holds across processes and machines sharing the bucket. Read the [requirements](/rowboat/deploy/storage/) first.

## Config

| Key | Meaning |
| --- | --- |
| `endpoint` | endpoint URL for stores other than AWS S3 (`https://<account>.r2.cloudflarestorage.com`); omitted means AWS S3 in `region` |
| `bucket` | must exist |
| `region` | such as `us-east-1`; most compatible stores accept any value |
| `prefix` | path inside the bucket under which every key is stored, such as `skein/prod` |
| `access_key_id_env`, `secret_access_key_env` | environment variables with the credentials |
| `allow_http` | allows plain `http://` only to `localhost` or a loopback address |

No request is made at startup; a missing bucket or wrong credentials show up on the first operation.

## Behavior

- Create-if-absent is `If-None-Match: *`, update is `If-Match` on the ETag; a failed condition is a conflict.
- Listing relies on the store returning keys in byte order, as S3 does.
- Every value is one `PutObject`; no multipart uploads, so values are limited to 5 GiB.
- With single-part uploads the ETag is the MD5 of the content, so writing identical bytes again yields the same version. Enable bucket versioning if a version must prove that no write happened in between.
- Errors carry only the kind of failure; values are never logged.

## Lifecycle

Add a lifecycle rule that expires `{prefix}/tenants/*/blobs/` after the time consumers need (for example 30 days). Consumers can bring expired blobs back with a `refetch` command while the provider still has them.
