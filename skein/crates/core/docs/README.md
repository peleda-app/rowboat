# skein-core

Plain data shared by every module: ids, hashes, timestamps, events and commands. No I/O. `NodeId`, `FencingToken` and `InvalidId` come from `baton-core`, the types crate of Baton, the coordination library Skein uses for leases, liveness and signals. Events and commands are the journal's wire format, so their JSON form is a public contract.

## Public API

| Item | Guarantees |
| --- | --- |
| `TenantId`, `AccountId` | 1–64 characters of `[a-z0-9_-]`, not starting with `-` and never a Windows device name (`con`, `nul`, `com1`, `lpt9`, ...): Baton's id rules; checked on construction and on deserialization, so always safe as one storage key segment. A `TenantId` also never starts with `_`: those ids are reserved for Skein's own groups (the group nodes heartbeat in), so no API can register, purge, export or read them; only `coordination::tenant` yields such a value, and `TenantId::is_reserved` says so |
| `NodeId`, `GroupId`, `LeaseKey`, `InvalidId` | re-exported from `baton-core`: the same rules as `TenantId`; `NodeId` is serialized as the same JSON string as before |
| `coordination` | the one mapping between Skein's ids and Baton's: `group(tenant)` and `tenant(group)`, `lease_key(account)` and `account(key)`, each keeping the id, total and one to one (a group starting with `_` maps to a reserved tenant). A tenant's leases, heartbeats and signals live in its group; the lease on an account's key makes a node the account's owner |
| `BlobHash` | BLAKE3 of the bytes, shown as 64 lowercase hex digits; `matches` compares in constant time |
| `Seq` | position in one account's log, from 1, consecutive |
| `FencingToken` | re-exported from `baton-core`; grows on every change of owner (lease holder); storage refuses writes with a lower token than it has seen; serialized as a plain number, as before |
| `Timestamp` | milliseconds since the Unix epoch |
| `Event` | `v` (schema version), `seq`, `at`, `account`, `key` (same for the same change seen twice), optional `origin` command and `trace` (W3C `traceparent`), `body` |
| `EventBody` | `collection_upserted`, `collection_deleted`, `object_upserted` (iCalendar or vCard blob with its version), `object_removed`, `mailbox_upserted`, `mailbox_deleted`, `message_added` (with blob hash and size), `message_removed`, `flags_changed`, `labels_changed`, `resync_required`, `first_sync_completed`, `account_health_changed`, `write_applied`, `conflict`, `write_failed`, `write_uncertain`, `send_result` (refused recipients with code and permanence, where the sent copy is: `provider`, `saved`, `failed`, optional `message_id` (the `Message-ID` recipients got when the sending service replaced the message's own; a copy the engine saved carries it, with the original in `X-Skein-Original-Message-ID`) and `provider_message_id` (the service's own id, such as an SES `MessageId`), and `dry_run: true` for a dry run that passed every check; omitted when false), `itip_received` (a message's iTIP part as a blob with an `ItipSummary`), `schedule_result` (`via`: `server`, `mail` or `none`, each iMIP message with its status, or a reason), `account_capabilities` (`MailCapabilities`, journaled when they change); unknown types from newer writers parse as `Unknown` |
| `Command`, `CommandBody` | `id` is a canonical ULID and the idempotency key; `set_flags`, `move`, `delete`, `append`, `refetch`, `send` (`blob`, `envelope`, optional `save_to_sent` mailbox, `send_at`, and `dry_run` that checks everything and sends nothing; `dry_run` defaults to false and is omitted when false), `put_object` and `delete_object` (optional `notify`), `respond_object` (`answer`, optional `attendee`, `comment`, `if_version`, `notify` on by default), `respond_invitation` (`invitation` blob, `answer`, optional `attendee`, `comment`, `save_to_sent`); `delete` with optional `to_trash`, `copy`, `set_labels`, `create_mailbox`, `rename_mailbox`, `delete_mailbox`, `append` with optional `received_at`; `is_collection_command`, `is_send` |
| `PartStat`, `ItipSummary`, `ScheduleVia`, `ScheduleMessage` | an answer (`accepted`, `declined`, `tentative`); the facts of an iTIP message; who told the other side of a scheduling command and what became of each message |
| `CollectionInfo.role` | `schedule_inbox` for a CalDAV scheduling inbox, absent for ordinary collections |
| `SendEnvelope`, `Dsn` | `from` and `to` (1 to `MAX_RECIPIENTS` = 500) as bare addresses; `check()` refuses anything that could end a header or an SMTP command (whitespace, control characters, `<>,;"`), more than 320 bytes, or no `@` with text on both sides, and its error never repeats an address; optional DSN `notify` (`never`, `success`, `failure`, `delay`) and `ret` (`full`, `headers`) |
| `AccountStatus`, `DomainStatus`, `SyncOutcome` | the per-account status record the owning node keeps (`mail`, `pim`, `send`, each absent until tried, and the writer's `fence`); per domain the latest `outcome` (`ok`, `auth_failed`, `config`, `throttled`, `network`, `protocol`, `storage`, `other`; unknown kinds parse as `other`), `last_ok_at`, `last_error_at`, the latest failure's `error` kind (kept after recovery), `resync_required` and `updated_at`. Kinds only, never provider text. `SyncOutcome::health` maps to `AccountHealth` as `account_health_changed` does; `AccountStatus::health` is the worst over the domains present |
| `Flags` | sorted, unique IMAP flags and keywords |
| `Credentials` | password, access token, or access key pair (`AccessKey { id, secret, session_token }`, for request signing); `Debug` never shows any part of them |
| `TlsRoots` | extra trust anchors; never turns verification off. `testing` feature: a throwaway CA |
| `SCHEMA_VERSION` | the event version this build writes |
