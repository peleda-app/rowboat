# skein-mail-jmap

The mail contract (`skein-mail`) on JMAP servers (RFC 8620 for the core, RFC 8621 for mail), such as Stalwart, Fastmail or Cyrus. `JmapProvider` discovers the session, turns each mailbox into a change feed whose cursor holds the account's `Email` state, downloads each email's original RFC 5322 bytes as a blob, carries out writes with `Email/set`, uploads and `Email/import`, and watches the account through the session's event source. Reading uses only `Mailbox/get`, `Email/get`, `Email/query`, `Email/changes` and blob downloads, so it never changes keywords.

## Public API

- `JmapProvider::new(settings, credentials) -> Result<JmapProvider, MailError>`: `Credentials::Password` signs in with HTTP Basic as `settings.username` (`Config` without one), `Credentials::AccessToken` with a bearer token (an OAuth token or an API token such as Fastmail's). An unusable address or an extra root that is not a certificate is `Config`, before anything is sent.
- `JmapProvider::with_timeout(d)`: every request gets `d` (default five minutes).
- `JmapProvider::with_push_ping(d)`: the event source is asked to ping every `d` (at least a second; default a minute).
- `JmapProvider::with_max_download(bytes)`: blob downloads above `bytes` (default 256 MiB) are `Protocol`.
- `session_url(input)`: the session address for what someone typed: `https://` is added when the scheme is missing, an address without a path gets `/.well-known/jmap`; only `https`, or `http` to `localhost`, `127.0.0.0/8` or `::1`; no credentials in the address.
- `MailProvider::connect` asks for the session each time. `MailProvider::watch` is described below.
- `JmapSettings { url, username, roots }`; its `Debug` hides the user name, and `JmapProvider`'s hides the credentials.

## Session and security

A session address under `/.well-known/` is followed through its redirects (at most five, never from https to http) without credentials; the session itself is then asked with credentials and a redirect of that request is refused (`Protocol`), so credentials never go to a host the configured address did not lead to. The session must offer `urn:ietf:params:jmap:mail` (`Config` otherwise) and name a primary mail account. Its `apiUrl`, `downloadUrl`, `uploadUrl` and `eventSourceUrl` may be on other hosts (Fastmail downloads from another domain) and must be `https` or loopback `http`; API calls and downloads follow at most five redirects, never away from https, and the HTTP client drops credentials on a redirect to another origin. `maxObjectsInGet`, `maxObjectsInSet` (both capped at 500), `maxCallsInRequest` (capped at 16) and `maxSizeUpload` are respected. Logs carry counts only; error texts name the host, never ids, mailbox names, addresses or secrets.

## Ids and cursors

- Mailbox ids are JMAP mailbox ids; paths join names from the top with `/`. Roles `inbox`, `sent`, `drafts`, `trash`, `junk`, `archive`, `all` and `flagged` map to `MailboxRole`. Every mailbox is selectable, none is a label. An email in two mailboxes is a message in each, with the same id.
- Message ids are JMAP email ids; `uid` is always `None`. Keywords set to `true` become flags: `$seen`, `$flagged`, `$answered` and `$draft` take IMAP's names (`\Seen`, ...); keywords in the IANA IMAP keyword registry take their registered spelling (`$forwarded` reads as `$Forwarded`, `$mdnsent` as `$MDNSent`), since JMAP keywords are case-insensitive and servers lowercase them; others stay as the server writes them. `received_at` is `receivedAt`.
- A feed starts with the account's `Email` state and a paged listing (`Email/query` with `inMailbox`, sorted by `receivedAt`, paged by `anchor` after the last email seen, with `Email/get` through a back-reference). An anchor that vanished mid-listing (`anchorNotFound`) restarts the listing; emails already reported are not reported again. After the last page `more` stays `true` once, and the next call reads `Email/changes` since the state taken before the listing, so nothing that changed during the listing is lost. Later calls read `Email/changes` with `maxChanges` = `limit` and `Email/get` for the created and updated ids, plus `Mailbox/get` for the mailbox (`MailboxNotFound` once it is gone).
- The cursor holds the mailbox and account ids, the `Email` state, the listing anchor while listing, and for every email seen in the mailbox a 64-bit hash of its id with a 32-bit hash of its keywords (12 bytes per email, zstd-compressed). An email created or updated is `Added` when it is in the mailbox and unknown, `Flags` when known with other keywords, nothing when only other properties changed, and `Removed` when known and no longer in the mailbox; destroyed emails that were known are `Removed`.
- `Reset`: `cannotCalculateChanges` (the server no longer knows the state), or a cursor that does not decode or belongs to another mailbox or account, starts a new listing, reported as `Reset { reason: "state" | "cursor" }`.
- `fetch`: `Email/get` for `blobId` and `mailboxIds`, then downloads through `downloadUrl`, four at a time, in the order asked. Emails no longer in the mailbox, not found, or whose blob is gone (`404`) are left out.

## Watch

`watch` opens the session's `eventSourceUrl` (RFC 8620 §7.3) with `types=Email,Mailbox`, `closeafter=no` and the ping interval, and returns `Changed { mailboxes: None }` for each `StateChange` naming the account with `Email` or `Mailbox`; other accounts, types and malformed events are skipped. No bytes for two and a half pings, or a closed stream, is `Network`; events above 1 MiB are `Protocol`. `Ok(None)` when the session names no event source. Dropping the watch closes the connection.

## Writes

`capabilities` reads every mailbox once (`Mailbox/get` with `role` and `myRights`): system flags `\Seen`, `\Flagged`, `\Answered` and `\Draft`; `keywords` unless every mailbox says `maySetKeywords: false`; `trash` when a mailbox has the `trash` role; `copy`, `append_received_at` and `mailboxes` always; `labels` never, because mailbox membership is how this crate models mailboxes.

- `SetFlags`: the mailbox is checked first (`MailboxNotFound`), then one `Email/set` (chunked by `maxObjectsInSet`) patches `keywords/<name>` to `true` or `null`; a flag in both lists ends up set. A flag JMAP cannot spell (such as `\Deleted`, or one with spaces or `( ) { ] % * " \`) is `Failed { reason: "unsupported_flag" }` before any request; other keywords are sent lowercased.
- `Move` and `Copy`: both mailboxes are checked in one `Mailbox/get`: a missing source is `MailboxNotFound`, a missing target `Failed { reason: "no_such_mailbox" }`. A move patches `mailboxIds/<from>` to `null` and `mailboxIds/<to>` to `true`; a copy only adds `mailboxIds/<to>`, so the copy is the same email (same id and blob) listed in both mailboxes, and deleting it from one leaves the other. Either into the same mailbox changes nothing.
- `Delete` for good: an email also in other mailboxes only leaves this one; an email only here is destroyed, which on JMAP is permanent. The changes are sent with `ifInState` set to the state the emails were read at; `stateMismatch` reads and plans again, up to five times, then the command is `Throttled { retry_after: None }` so it is tried again later. When none of the emails is in the mailbox, a missing mailbox is `MailboxNotFound`, otherwise `Applied`.
- `Delete` to the trash: a missing mailbox is `MailboxNotFound`, no mailbox with the `trash` role `Failed { reason: "no_trash" }`, a delete from the trash itself `Applied` without a change. Otherwise each email in the mailbox gets `mailboxIds` set to the trash alone, so it leaves every other mailbox too, as JMAP clients do.
- `Append`: an unknown mailbox is `MailboxNotFound`, more than `maxSizeUpload` is `Failed { reason: "too_large" }`; the bytes are uploaded unchanged as `message/rfc822`, then `Email/import` puts the blob in the mailbox with the flags as keywords and `received_at` as `receivedAt` (whole seconds, UTC); without it the server uses the import time.
- `CreateMailbox`: the path is split at `/` (an empty level is `Failed { reason: "invalid_path" }`) and matched against the mailbox names level by level; when it exists the command is `Failed { reason: "exists" }`. Missing parents are created in the same `Mailbox/set`, referring to each other by creation id.
- `RenameMailbox`: a missing mailbox is `MailboxNotFound`, one with any role `Failed { reason: "protected" }`, a path that clashes with another mailbox `exists`, a path under the mailbox itself `invalid_path`, its own path `Applied` without a change. One `Mailbox/set` updates `name` and `parentId`, creating missing parents as above.
- `DeleteMailbox`: a missing mailbox is `MailboxNotFound`, one with any role `Failed { reason: "protected" }`; otherwise `Mailbox/set` destroys it with `onDestroyRemoveEmails: true`, so emails only in it are destroyed and emails also elsewhere stay there. One with child mailboxes is `Failed { reason: "has_children" }` (`mailboxHasChild`); one already gone counts as deleted.
- Outcomes: emails already gone (`notFound`) count as done; any other per-email or per-mailbox refusal is `Failed { reason: <JMAP error type> }` (`alreadyExists` becomes `exists`), and emails earlier in the command may already be changed (each patch is idempotent, so the command can be repeated). Errors before the change is sent (`Auth`, `Config`, `Throttled`, `MailboxNotFound`) mean nothing changed; a request that went out without a usable answer, or a `5xx` other than throttling, is `Uncertain`. `SetLabels`, `Refetch` and commands for other services are `Failed { reason: "unsupported" }`.
- Every check above is a separate request before the change, so a mailbox deleted or renamed in between by someone else surfaces as the server's refusal instead.

## Errors

`401` and `403` are `Auth`; `404` on the session address is `Config`; `429`, and `503` with `Retry-After`, are `Throttled { retry_after }`; other `5xx`, timeouts and broken connections are `Network`; other refusals, method-level errors and malformed answers are `Protocol`. JSON answers above 64 MiB are `Protocol`.

## Limits and not done

- `Mailbox/changes` is not used: `mailboxes` lists everything with one `Mailbox/get`, and each `changes` call checks its mailbox with `Mailbox/get` by id in the same request.
- `Email/queryChanges` is not used: many servers cannot calculate it for `inMailbox` filters, and `Email/changes` with the cursor's hashes covers the same ground.
- A mailbox name containing `/` reads as a deeper path.
- Tested against the in-process fake JMAP server in `src/tests.rs` (the mail conformance suite with a password and with a bearer token under one-object, one-call limits; paths and roles; moves; changes during a paged listing; a lost anchor; unreadable and foreign cursors; vanished mailboxes; well-known discovery and a refused session redirect; throttling; size limits; every write including `ifInState` retries and emails in two mailboxes; the write conformance suite under normal and one-object, one-call limits; trash, copy, missing mailboxes, nested mailbox creation, renames and deletions with their refusals; `receivedAt` on import; a lost import answer; the event source, its silence and its absence; and no secrets or content in logs, errors or `Debug`), and against Stalwart 0.16 in the integration stack (engine round trip, a watch woken by an appended message, and the write conformance suite in `tests/integration/tests/jmap_write.rs`, which creates a top-level `skein-write-other` mailbox once and keeps it). Stalwart needed no workarounds: its trash is `Deleted Items` with the `trash` role and it honours `receivedAt` (checked by the suite); creation-id parents, `alreadyExists` for a name clash, `mailboxHasChild`, and refusing a move under itself (`invalidProperties`, which the provider catches first as `invalid_path`) were checked by hand against 0.16.27. Not yet against Fastmail or Cyrus.
