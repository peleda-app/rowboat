# skein-integration

- `tests/it.rs`: against containers from `compose.yaml` (RustFS and Versity S3 Gateway, GreenMail, Dovecot, Stalwart). The storage conformance suite runs against both S3 servers to check they still meet [the requirements](../../../docs/REQUIREMENTS.md); every other suite runs against Versity; run with `mise run it`. The journal on S3 is read by another store instance and fenced across two nodes; the mail round trip (append, sync, flag, delete) through the engine runs over IMAP against GreenMail, Dovecot (real `CONDSTORE`, `QRESYNC`, `NOTIFY`, `MOVE`, `UIDPLUS`) and Stalwart, and over JMAP against Stalwart, whose event source must also wake a watch when a message is appended. A `send` command goes through the engine and `skein-send-smtp` to GreenMail SMTP and must arrive in the INBOX over IMAP; `skein-send-jmap` sends to Stalwart and the message must show up both in Sent (the server's own copy) and in the INBOX. Scheduling: an organizer's event with `notify` on Radicale (which does not schedule) makes the engine mail a `REQUEST` through GreenMail SMTP; syncing the attendee's INBOX journals `itip_received`; `respond_invitation` and `respond_object` mail two `REPLY`s that arrive in the organizer's GreenMail mailbox, and the answer is in Radicale's copy. Against Stalwart, an answer through JMAP lands on the right participant and on an instance with its own answer; over CalDAV, Stalwart advertises `calendar-auto-schedule`, names the account in `calendar-user-address-set`, lists its scheduling inbox, and an organizer's `put_object` with `notify` and an attendee's `respond_object` are left to the server (`schedule_result` says `server`).
- Services listen on `127.0.0.1` only, without TLS: GreenMail IMAP on 49143 and SMTP on 49025 (no sign-in), Dovecot IMAP on 49243 (user `ada`, password `it-password`), Stalwart HTTP/JMAP on 49280 and IMAP on 49244 (user `ada@example.com`, password `it-stalwart-password`). `seed/dovecot/skein.conf` allows plain-text sign-in; `seed/stalwart/seed.sh` configures a fresh Stalwart volume once (domain, listeners, no rate limits, the user). `mise run it-down` removes the volumes.
- `tests/live.rs`: against real accounts, see [docs/LIVE.md](../../../docs/LIVE.md); run with `mise run live` or the Live providers workflow.

Both skip unless their environment is set, so `cargo test --workspace` stays network-free.
