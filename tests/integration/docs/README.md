# rowboat-integration

The node (`rowboat-node`, through `NodeApi` only) against real IMAP and SMTP servers in local containers, over TLS as in production. Run with `mise run it`: Skein's suites first, then this one even when Skein's failed, then the stack, its volumes and the test CA go down (`ROWBOAT_IT_KEEP=1` keeps them up; `mise run it-down` takes them down later). On a failure the containers' logs land in `.logs/compose.log`, which CI uploads. `SKEIN_IT_ARGS` and `ROWBOAT_IT_ARGS` pass cargo test arguments to one suite only; arguments after `it.sh` go to both. Without `ROWBOAT_IT=1` every test returns at once, so `cargo test --workspace` stays network-free.

## The stack

`compose.yaml` here is layered over `skein/tests/integration/compose.yaml` (`docker compose -f skein/... -f tests/integration/compose.yaml`; relative paths resolve from Skein's directory), so one `up` serves both suites. Every port is on `127.0.0.1`.

- **Test CA.** `it.sh` runs `rowboat-it-certs` (`src/bin/certs.rs`, rcgen) once into `.certs/` (ignored by git, removed by `it-down`): a throwaway CA and one server certificate for `mail.localhost`, `localhost` and `127.0.0.1`, valid for thirty days. The servers present it; the node trusts the CA only through `NodeBuilder::test_roots` (feature `testing`), which adds roots to the default IMAP and SMTP providers and the default `ServerProber`. Verification stays on and plain text stays refused: no production path is weakened. The suite connects to `mail.localhost`, which resolves to loopback on macOS and on Linux with systemd-resolved; `it.sh` stops with a hint when it does not.
- **Dovecot 2.4**: IMAPS 49293, IMAP with STARTTLS 49243 (Skein's plain port, now also offering STARTTLS), submissions 49265, submission with STARTTLS 49287; the certificate is mounted over the image's `ssl/tls.crt` and `tls.key`. The image's static password database takes any user name with the password `it-password`. Dovecot is not an MTA: `seed/dovecot/node.conf` relays submission to GreenMail's SMTP inside the compose network (its LMTP refuses `EHLO`), so mail to another Dovecot user is never delivered there.
- **Stalwart**: IMAPS 49393, IMAP with STARTTLS 49244, submissions 49365, submission with STARTTLS 49387, JMAP and the admin API on 49280. `seed/stalwart/seed.sh` runs Skein's seed, then installs the certificate (`x:Certificate`) and the three TLS listeners once per volume. `it.sh` then drops Stalwart's inbound SMTP throttles (five connections a second per address, created on the first normal start) and reloads its settings, or parallel tests get connections closed before the greeting. Users are created per test through `x:Account/set`.
- **GreenMail 2.1**: IMAPS 49193, SMTPS 49165, its API on 49180 (users are created per test through `POST /api/user`). `seed/greenmail/greenmail.sh` builds the PKCS #12 keystore GreenMail reads from the PEM files with the image's own `openssl`.

Each test makes its own users (`<name><random>@example.com`), so runs never see each other and a kept stack can serve several runs.

## Scenarios (`tests/node.rs`), each on Dovecot, Stalwart and GreenMail

The node runs the test profile (250 ms heartbeats, a sync every second, a 300 ms undo window) over a temporary directory, the in-memory keystore and `rinse-mail-direct`. Accounts use implicit TLS on Dovecot and GreenMail and STARTTLS on both servers of Stalwart.

- **`mail_flow_*`**: 240 invented messages in INBOX (a third read) and 60 in `Projects` are appended with the suite's own IMAP client (`async-imap` over TLS, independent of Skein's providers); `add_account` by password; the first sync lists every message, with totals equal to the server's `STATUS` and the expected unread counts; a message is opened through `message_raw`, compared byte for byte, rendered by rinse and checked with `verify_rendered`; search for a word only one body holds finds exactly that message; mark read and flagged, move to `Projects`, archive, delete to the trash and delete for good are each checked on the server and then in the node (flags in the INBOX membership, exactly one membership in Projects, Archive or Trash, `NotFound` after deleting for good); a send settles `Sent`, its copy appears in Sent on the server and in the node, and on Stalwart and GreenMail it is delivered to a second account on the same server, which the node (holding both accounts) receives; a message appended while the node runs produces `NewMail` (the time it took is printed).
- **`lifecycle_*`**: a wrong password is `AuthFailed` and stores nothing (no object appears in the objects directory apart from lock files and the node's own heartbeat); after a first sync of 200 messages through a byte-counting loopback relay, the node is shut down and rebuilt over the same directory and keystore: the account, its first-sync state and its 200 messages are there before any sync; the restarted node polls only once an hour, so `sync_now` picks up one new message and everything the relay carried since the first node's shutdown must stay under a quarter of the first sync's bytes; the original of a message and the account's records are shown to be on disk, then `remove_account` deletes every object naming the account or its blobs except the keyring's tombstone for the destroyed scope, and the database lists nothing.
- **`discovery_*`**: `ServerProber::with_test_roots` (feature `testing`) with the test CA verifies IMAPS, IMAP with STARTTLS and SMTP; with another CA, or the web roots, it is `TlsFailed`; a closed port is `Unreachable`. `discover` with `rowboat-discover-autoconfig` over a fixed autoconfig file naming the container's ports returns one candidate, verified by probes and needing confirmation (the servers are outside the address's domain); a file naming a closed port returns nothing. `add_account` on a node that does not trust the CA is `TlsFailed`, and against a closed port `ServerUnreachable`; neither stores an account.

Not covered: JMAP (the node offers only IMAP and SMTP accounts in phase 1), OAuth, delivery between Dovecot users (no MTA in the image). The node suite takes about 25 s on an Apple silicon laptop once built.
